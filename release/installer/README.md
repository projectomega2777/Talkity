# Talkity installer (Inno Setup)

Builds `release\output\TalkitySetup.exe` from the compiled desktop client.

## Toolchain

| Item | Value |
|------|-------|
| Compiler | Inno Setup 6.7.3 (`ISCC.exe`) |
| Download | https://github.com/jrsoftware/issrc/releases/download/is-6_7_3/innosetup-6.7.3.exe |
| Installer SHA256 | `9C73C3BAE7ED48D44112A0F48E66742C00090BDB5BEF71D9D3C056C66E97B732` |
| Script | `release\installer\Talkity.iss` |
| Output | `release\output\TalkitySetup.exe` (gitignored) |

Inno Setup 6 is free for commercial use. The compiler is not vendored in this
repository; install it once:

```bat
innosetup-6.7.3.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /SP- ^
  /CURRENTUSER /DIR="%LOCALAPPDATA%\Programs\InnoSetup6"
```

`build_installer.bat` looks for `ISCC.exe` in
`%LOCALAPPDATA%\Programs\InnoSetup6`, `%ProgramFiles(x86)%\Inno Setup 6`,
`%ProgramFiles%\Inno Setup 6`, then `PATH`.

## Build

```bat
build_app.bat                        :: produces Talkity.exe (version-stamped, icon embedded)
release\installer\build_installer.bat
```

`build_installer.bat` fails if `Talkity.exe` is missing, so the installer can
never silently package a stale or absent binary. Close Talkity before running
`build_app.bat`; the C# compiler cannot overwrite a running executable.

The icon is generated by `make_icon.ps1` into `talkity.ico` and is also embedded
in `Talkity.exe` via `/win32icon` in `build_app.bat`. Replacing the brand mark
only requires regenerating that file.

## What the installer does

**Install**

* Per-machine into `{autopf}\Talkity` (`C:\Program Files\Talkity` on 64-bit
  Windows), requiring elevation.
  `PrivilegesRequiredOverridesAllowed=commandline` also permits a per-user
  install with `TalkitySetup.exe /CURRENTUSER`, which needs no admin rights and
  lands in `%LOCALAPPDATA%\Programs\Talkity`.
* Packages exactly one file: `Talkity.exe`. No sources, logs, tests,
  `node_modules`, settings, or build artifacts are included.
* Start Menu folder `Talkity` containing the app and the uninstaller.
* Optional desktop shortcut (`desktopicon` task, unchecked by default).
* Registers an Add/Remove Programs entry with the app icon, publisher and
  version.

**Upgrade**

* Stable `AppId` `{B1E4A7C2-9D63-4F58-8A2E-5C7D1B9F0E43}` makes the new
  package replace the old one instead of installing side by side.
* `UsePreviousAppDir` / `UsePreviousTasks` keep the user's install directory and
  shortcut choices.
* A running Talkity is closed before files are replaced (`PrepareToInstall`:
  graceful `taskkill`, then forced after 1.2 s).
* A silent upgrade of a running instance relaunches the app in the background
  afterwards, so unattended updates do not leave the user without a tray icon.
* The app's `HKCU\...\Run\Talkity` autostart entry is removed by the outgoing
  version's uninstaller and recreated after the upgrade when
  `%APPDATA%\Talkity\settings.json` still has `"launchAtStartup": true`.

**Uninstall**

* Removes the install directory, both shortcuts, the Add/Remove Programs entry
  and the autostart entry *only if* it points at the copy being removed.
* Never touches `%APPDATA%\Talkity`: settings, history and logs survive an
  uninstall and are reused by a later install.

**Prerequisite**

`InitializeSetup` requires .NET Framework 4.0 or later (registry `Release` /
`Install` check under `NDP\v4`). Windows 10 and 11 include it. No VC++ runtime,
no native libraries, no NuGet packages, no background services.

## Verification performed

See `release\RELEASE.md` for the full test log. Summary of what was actually
executed on this machine:

* Fresh per-user install, upgrade over a running instance, uninstall, reinstall
  with the desktop-shortcut task, and a second uninstall — all exit code 0.
* Shortcut targets, ARP metadata, install-directory contents and autostart
  entry checked before and after each step.
* User settings/history verified byte-identical after uninstall.

Not performed: the elevated per-machine path (this session had no admin rights),
and installation on a clean Windows VM. See "Remaining manual tests" in the
release notes.
